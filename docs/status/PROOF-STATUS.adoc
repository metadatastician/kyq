= Proof Status — kyq
:revdate: 2026-11-26

The per-claim proof record for kyq in the sense of
`hyperpolymath/standards` `3-practice/PROOF-POLICY.adoc` §8.5. A row says
only what a run in this repository supports. Obligations are listed in
`docs/PROOF_OBLIGATIONS.adoc`; the proofs and how to run them are in
`verification/proofs/`.

*State in one paragraph.* The P1 proof spine exists as an Agda development
(9 modules, 0 development postulates) and a Rocq recheck leg. Both are
committed (`e174f8c`, PR #29). On 2026-11-19 both legs passed in CI under
the pinned Guix provers, Agda 2.7.0.1 and Rocq 8.18.0, on commit `65b3204`
(see "Toolchains and deviations"), which closes DEV-1 and DEV-2. There is no
Lean leg.
The machine-readable receipt (§8.5.1) is
`verification/receipts/kyq-spine_praxis.deed`. It records the Agda run of
the P2 lane on `main` at `a06ff20`, and the pinned reader derives PWG-3 for
all 93 theory rows from it. No row is higher: no recheck leg is RECONCILED.
This file proves nothing about kyq's code, the JS conformance
oracle or ijson-jcs. The ledger for kyq's Rust code is
`verification/PROOF-STATUS.adoc` (Creusot/Pearlite, §5 tokens, no PWG).

*Home.* The spine is theory, and kyq is not meant to be its home. It is
placed here *provisionally* until owner decision D13 names the theory home
(open; see `verification/proofs/agda/README.adoc` for the arms and the
verify-canon M8 caveat). §8.5 records a grade in the theorem's home
repository, so these rows, the controls and any receipts move with the
spine when D13 is ruled.

== Vocabulary

* Status tokens (§5): `proven`, `proven-with-postulates`, `tested-only`,
  `argued` (= ASSUMED), `open`.
* Recheck routes (§2, §8.5): `transported`, `re-proved`, `waived`,
  `unavailable`, each with a §2.2 correspondence state (`BRIDGE-PENDING`,
  `RECONCILED`, ...). A leg with no route yet is written "route unset";
  the receipt writes it as `unavailable`, with a reason.
* Proof Witness Grades (§8): `PWG-3` < `PWG-2i` < `PWG-2ii` < `PWG-1`, or
  `ungraded`. A grade is derived from receipts and is never asserted here.

== Recheck legs

=== Rocq leg

Route `re-proved`, by hand. File `verification/proofs/rocq/KyqSpine.v`;
theorems `leq_total`, `leq_antisym`, `leq_trans`, `sorted_unique`,
`isort_unique`, `no_unique_without_distinct`, `canon_nf`, `nf_fixed`,
`canon_idem`, `canon_resp`, `nf_unique`, `tv_sound`, `tv_complete`,
`tv_iff`, `one_arg_not_tv`. It uses the Coq standard library shipped with
coqc (List, Permutation, Bool, Arith, Lia) and no other library.

*§2 reason for re-proof, and a departure from the default arm.* PROOF-POLICY
§2 says "transport first" (Agda → Dedukti/Lambdapi → Rocq). No transport was
tried: this session has no pinned Agda2Dedukti, Lambdapi or Dedukti→Rocq
exporter (`agda2dedukti`, `lambdapi` and `dkcheck` are not on `PATH`, and
there is no Guix). Re-proof is the §2 fallback where the pinned exporter has
no route; here there is no pinned exporter at all. Transport is the default
(elegant) arm (doctrine 15); re-proof is a departure from it, taken because
the default arm could not be run. The transport attempt is *owed*, and the
re-proved leg stays until a pinned exporter is available.

Correspondence state: *BRIDGE-PENDING*. The statement comparison with Agda is
written down in `verification/proofs/agda/README.adoc` ("Statement
correspondence"), and the differences it found are listed there. It was
drafted by an agent and has not been reviewed (doctrine 4), so the leg does
not count towards a grade. The runner's PASS line says so.

. `elan default stable` (elan 3.1.0 at `/usr/bin/elan`) failed:

  to parse latest release tag". The GitHub API
  (`api.github.com/repos/leanprover/lean4/releases/latest`) returned HTTP 403
  through the session proxy.
. `elan toolchain install leanprover/lean4:v4.15.0` failed: "could not
  download file from
  'https://github.com/leanprover/lean4/releases/expanded_assets/v4.15.0' ...
  http request returned an unsuccessful status code: 403".
. The release archive itself downloaded (`lean-4.15.0-linux.zip`, sha256
  `8eceac177fe2e2828f71add0d458e6a91187ce6d4f67d0f0364061b9e3dca59b`), but
  unpacking and linking it as an elan toolchain was refused by the session's
  permission policy, so no Lean binary was run.

No Lean source was written: an unchecked file would read as a leg that does
not exist. §2 requires every Agda theory theorem to be rechecked, so the
Lean target is 0 of 93. `just proofs` exits 3 until the leg exists.

== What is NOT proven

* *kyq's code.* This spine proves nothing about the Rust implementation
  (`src/*.rs`). Its proof route is Creusot with Pearlite contracts
  (PROOF-POLICY §1.2), recorded in `verification/PROOF-STATUS.adoc`: only the
  budget arithmetic is `PROVEN` there, and the parser, map, alias, formatter,
  pointer and CLI obligations are `OPEN`. The retained AffineScript sources
  are historical research and are not built.
* *The JS conformance oracle* (`conformance/`). Its gates and differential
  runs are tests: `tested-only`. The spine is a model of what the oracle
  should satisfy, not a proof that it does.
* *Gate-level closure for kyq's check (R3).* `check(canon x) = OK` is proved
  only for the reference check of the model (`gate-closure`,
  `profile-gate-closure`). For kyq's `check` it is `open` (proposed JCS-10).
  Likewise non-malleability of kyq's `check` (proposed JCS-11) is `open`.
* *Headers and trivia (open definitional gap).* `CanonicalGate` requires
  `b ≡ c v` exactly. verify-logic L3 asks for `b = h ++ c v` with a
  preserved header `h`. Without it, any KYAML instance must refuse every
  SPDX-headed file (CORRECTIONS blocker 2, doctrine 6). The header form needs
  a byte model, which P1 does not have. It blocks any KYAML instance.
* *Bytes.* No parser, printer, UTF-8 encoding, escaping, whitespace or
  newline rule is modelled; `ProfileFormat`'s texts are token trees. So
  JCS-3, JCS-5(b), JCS-5(c), JCS-7, JCS-8, JCS-9 and the byte halves of JCS-4,
  JCS-5(a) and JCS-6 are `open` (see "Catalogue status").
* *Number text.* `show-val` (Number::toString round trip) is a hypothesis of
  `NumIface`; no shortest-round-trip printer is mechanised anywhere known.
* *KYAML, TOML, Dhall.* Only the abstract `CanonicalGate`/`ValidityGate`
  definitions exist. KYAML-1..10, K8s-1..7, Q-1..5 are `open`.
* *SEC-1 beyond budget closure.* Depth, node and UTF-8 string-byte budgets
  are closed under canon. Alias-expansion budgets (KYAML), the encoded-bytes
  CLI limit, termination, time and memory are `open`.
* *JCS-1 itself.* Only its necessity is shown; that the parser rejects
  duplicate names is `open`.
* *FID-1 grade composition.* Faithful≈ composes (`faithful-compose`); that
  the grade composes by max is `open`.

== Trust boundary

* `ASSUMED`: the Rust compiler; the dependencies `yaml-rust2`, `serde_dhall`
  and `ijson-jcs` (`verification/README.adoc`); the JS engine's
  `Number::toString` (for the conformance oracle);
  `ryu_js` in ijson-jcs; the `show-val` hypothesis of `NumIface` (a module
  parameter, not a postulate, but nothing discharges it).
* *Format instances, `sem` and `img`.* `≈` is the kernel of a `Format`'s
  `norm`, which the `Format` chooses. Every Faithful≈ claim is only as good
  as an audited, exported `Format` instance, the independently defined
  equivalence `sem` it is shown to separate (`NormSeparates`), and the image
  predicate `img` of `Covered≈`. These are definitions, not theorems; no
  instance for kyq's real formats exists yet. `coarse-norm-faithful` shows
  what an unaudited instance allows.
* *Rust.* kyq's implementation is Rust. *Creusot* with *Pearlite* contracts
  is the verifier for it (PROOF-POLICY §1.2). *Verus* scopes are recorded in
  `verification/PROOF-STATUS.adoc` and are left to the owner. Those results
  use §5 tokens and are not witnesses for any theorem in this file.
* *Rust dependency `hyperpolymath/ijson-jcs`.* Creusot/Pearlite and Verus:
  token `open`, not run (out of repo). Scope that a proof would need for kyq:
  `to_jcs`, number serialisation (the RFC 8785 §3.2.2.3 path through
  `ryu_js`), and the byte-level properties kyq relies on (JCS-4 order,
  JCS-6, JCS-8 byte equality). Next action: owned by ijson-jcs, a tracking
  issue there (not opened from this session). ijson-jcs has no proof files;
  its byte equality with kyq (JCS-8) stays `tested-only` until both sides are
  proved against one specification. Running both verifiers would not make
  two independent witnesses (§1.2).
* Provers' trusted bases: the Agda 2.6.3 kernel and the 4 named postulates of
  `Agda.Primitive` listed under Receipts; the Coq 8.18.0 kernel and its
  standard library.
* Development postulates and axioms in the spine: none.
