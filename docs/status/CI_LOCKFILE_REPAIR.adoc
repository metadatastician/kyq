== Root cause: two lockfiles, not an allowlist gap

The failing diagnostic was:

[source,text]
----
Unable to resolve action `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1`:
invalid lockfile pin. Run `gh actions-lock` to update the lockfile
----

A full-SHA dependency key whose `ref` is that same SHA is invalid. Upstream
`github/gh-actions-lock` PR
https://github.com/github/gh-actions-lock/pull/198[#198] and commit `dacafb7`
state this explicitly and implement the repair: record an exact tag at the
commit, or a branch containing it, while retaining the immutable `commit`
field. Released v0.4.0 (`759f9c2d44e8599fa5b29224e5a30c58b3555211`) contains
that implementation.

There are two relevant lock scopes:

. kyq's caller `.github/workflows/actions.lock`;
. the called `hyperpolymath/standards` lock at the reusable-workflow SHA.

Repairing only scope 1 was insufficient. Commit `55cfdff` changed all 11
caller own-SHA `ref` fields, but these controls still failed every `Set up job`
with the same checkout diagnostic:

The pinned standards revision `0b1898e2e6a0fc88348c0f2517970593d373ca10`
still carried the invalid called-side metadata. The selected revision
`cf8f91219d80da55cf8cbbfcd587d00c2d8798ed` has symbolic refs for every action
leaf used by kyq, including `actions/checkout@v7.0.1` metadata for the same
immutable checkout commit. It is an ancestor of standards `main` (`compare`
reported `ahead`, `behind=0`). No action allowlist or Actions policy was
changed.

== Changes

=== Caller metadata and regression gate — `55cfdff`

Eleven caller entries changed only their `ref` metadata. Eight action commits
have exact semver tags; three reusable-workflow commits have no exact tag and
are contained by `main`. Keys, commits, owner/repository IDs, and transitive
edges stayed unchanged.

`scripts/check-action-pinning.js` now rejects an own-SHA `ref` instead of
reporting a false pinning PASS:

* before the repair: exit 1, exactly 11 findings;
* after the repair: exit 0, `all action refs are pinned`;
* planted single-entry checkout control in a temporary directory: exit 1,
  exactly the planted finding.

This local check does not replace GitHub's resolver or the lock-sync gate.

=== Called-side pin and closure — `009cbcd`

All six standards callers moved from `0b1898e…` to `cf8f9121…`: Governance,
Secret Scanner, Rust CI, Scorecard, Hypatia, and Mirror. The lock was updated
atomically with standards' purpose-built `relock-standards-pin.sh`, then the
new reusable root received symbolic `main` metadata to satisfy the same
own-SHA rule.

The closure diff adds the two new Governance action dependencies
(`denoland/setup-deno` and the bare-SHA `oven-sh/setup-bun` record) and retains
all existing immutable commits. The temporary v0.4.0 generator evidence was
not used as the final lock: full generation prunes job-level reusable roots,
a documented generator limitation. The purpose-built relock preserves them.
