= Executable capabilities (preview contract)
:revdate: 2026-11-26

== Purpose

A consumer must not guess whether an operation is safe for a format from
the existence of its parser. The command below reports *implemented,
tested* CLI operations, bounded values, and explicit missing guarantees:

[source,sh]
----
kyq --capabilities
----

The command writes exactly one JSON document followed by LF to stdout,
requires no input or source checkout, and rejects additional arguments
with exit code 2. It is also available from packaged native executables.

The +schema_version+ is +0.3.0+ and +contract_status+ is +preview+.
Consumers may inspect or test it today, but must not assume that this
provisional schema is a stable public ABI. Any incompatible schema change
requires an explicit version change and corresponding fixture update.

== Source of truth

The reporting implementation is +src/capabilities.rs+ and the actual CLI
dispatch is +src/main.rs+. +tests/capabilities.rs+ independently executes
every advertised format-operation pairing and checks that unsupported
pairs refuse rather than silently projecting a value.

The report describes exactly five input selector names:

[cols="1,3,2",options="header"]
|===
|Selector |Commands |Semantics
|+kyaml+ |validate, canon, to-json, fmt, get, check, fix |Restricted KYAML; legacy two-space block formatter, NOT KEP-5295 flow
|+json+ |validate, canon, to-json, fmt, get, check, fix |Estate strict I-JSON with R3 floating-integer closure
|+jcs+ |validate, canon, to-json, fmt, get, check, fix |Explicit RFC 8785 binary64 reader, not a backdoor into strict I-JSON
|+dhall+ |validate, canon, to-json, fmt, get |Typed import-free Dhall; check is unsupported
|+toml+ |validate |TOML 1.0 validity only; querying and conversion refuse
|===

The +fmt+ command produces *legacy block KYAML*, even when the input
format was JSON, JCS or Dhall. +canon+ emits RFC 8785 JCS bytes without
an LF; +to-json+ adds one LF. +get+ emits one JCS value plus LF for each
parsed document. +check+ compares the file bytes with the canonical
file form and never rewrites the file.

+fix FILE+ (since schema 0.2.0) is the only command that writes. It follows
owner ruling A-06 (2026-11-26): it fails closed. For KYAML the canonical
file form is the leading header comment block (every comment and blank
line before the first content line, so the SPDX lines), byte for byte,
then the +fmt+ body. A comment anywhere else makes +fix+ refuse with
+COMMENTS_WOULD_BE_LOST+ and its line and column; the file is not
touched. For JSON and JCS the form is the JCS bytes plus one LF. Dhall
and TOML refuse with +UNSUPPORTED_OPERATION+. +check+ accepts exactly
what +fix+ writes, so +check+ after +fix+ exits 0. +fix+ prints
+OK FILE+ or +FIXED FILE+ on stdout.

+fix+ never reads stdin and refuses symbolic links and non-regular
files. It writes a temporary file in the same directory, syncs it,
reads the original again and stops with +CONCURRENT_MODIFICATION+ if it
changed, then renames the temporary file over the original. It keeps
the permission bits, not the owner, extended attributes or hard links.
An invalid input, a refusal or an I/O error leaves the file as it was.

The comment rule errs toward refusal. A +#+ that cannot be shown to be
quoted or block scalar text counts as a comment. One known case refuses
a file the JS oracle accepts: a +#+ content line inside a block scalar
with an explicit indentation indicator (+|2+).

== Important missing assurances

The report provides numeric limits that actually exist:
+raw_input_max_bytes+, +kyaml_nodes_max+,
+kyaml_expanded_storage_max_bytes+ and
+kyaml_container_depth_max+.

The native KYAML reader accepts up to 64 containers on a root-to-leaf
path after alias expansion. An empty sequence or mapping counts as one
container and a scalar counts as zero. An alias uses the depth available
where it appears. A 65th container produces +DEPTH_LIMIT+. The R3
conformance oracle has its own limit of 127 containers.

Schema 0.3.0 (W7, 2026-11-26) confines Dhall. The CLI never evaluates
Dhall in its own process: it re-runs itself as a hidden worker
(+safety.dhall_confinement: "worker-process"+). The parent kills the
worker after +dhall_process_time_limit_ms+ (2000) and refuses with
+DHALL_TIME_LIMIT+. The worker caps its own heap at
+dhall_process_memory_limit_bytes+ (268435456, 256 MiB) through a
counting global allocator, so an allocation past the cap ends it, and
the parent refuses with +DHALL_MEMORY_LIMIT+. The cap is the same on
Linux, macOS and Windows; it counts heap, not stack. Deep evaluation
that overflows the worker's default main-thread stack is
+DHALL_STACK_LIMIT+ (before W7 it aborted kyq itself). A result larger
than +dhall_result_max_bytes+ (64 MiB) is +DHALL_OUTPUT_LIMIT+. Any
other abnormal worker end is +DHALL_WORKER_FAILED+. All of these exit 2.
The limits bind the +kyq+ CLI only: the +kyq::parse+ library function
still evaluates in-process, and a library caller must supply its own
limits. The report also states +fmt_preserves_comments: false+,
+atomic_fix_implemented: true+, +fix_keeps_header_comment_block: true+,
+fix_refuses_lost_comments: true+ and +fix_follows_symlinks: false+.
+output_contract.writes_input_files+ is +true+, and
+writing_operations+ lists only +fix+.

+diagnostics.machine_readable+ is +false+: the current CLI reports
human-readable errors on stderr with exit 2, and exit 1 indicates
canonical drift. The machine-readable *capability report* is not a
machine-readable *diagnostic protocol*.

No release, formal proof status, external provenance, platform
availability, service-mode interface or wider kyX format list is
implied by this record. It reports compiled behaviour, not planned
features. kyX remains a separate application; it may eventually
negotiate against this surface without consuming kyq's internal Rust
Value enum.

== Compatibility discipline

Call +--capabilities+ with no other arguments. Read the
+schema_version+ and +contract_status+ first. Interpret only
advertised operations, format selectors and safety statements;
unknown fields may be ignored by tolerant readers. A consumer
must still independently enforce the deadline and process isolation
suitable for its threat model.

Use +cargo test --locked --test capabilities+ for a live
dispatch-versus-report check; the normal cross-platform CI will
also run the test. The field values must change when implementation
limits or operations change, and the tests must fail if the report
overstates implemented functionality.
