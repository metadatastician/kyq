= kyq v0.3 Ultraplan — From Scaffold to Guaranteed KYAML + JCS Canonicalisation and Estate Integration
:toc: macro
:toclevels: 3
:icons: font
:revdate: 2026-10-23
:author: Agent (Arena) + hyperpolymath

Abstract: a field-ready plan to take `metadatastician/kyq` from an honest
scaffold (Phase 0: 5% milestones, build does not parse) to a tool that
*guarantees* it works for KYAML (Kubernetes YAML, a well-defined YAML 1.2
subset) and for the estate JSON canonical form defined by
`hyperpolymath/ijson-jcs` (I-JSON RFC 7493 + JCS RFC 8785), then integrate it
throughout `hyperpolymath/MetaManifold-WebUI`. The plan is ordered by hard
dependency: first the repository must be truthful, green in CI, documented and
secure; then KYAML must be proved working; then the JCS canonical pipeline must
be proved working on top of KYAML; then packaging, integration, and evidence.
Mathematical proofs are catalogued, not discharged, in this document. This
revision integrates the 40-step production integration handover (2026-10-23) as
the normative Phase 1–6 breakdown.

== How to read this document

* *Honest* means no placeholder binary, no fake test pass. The `Justfile`
  recettes `build`, `test`, `bench`, `wasm` currently fail with
  `not implemented: AffineScript 0.1.1 does not parse src/`. That is load-bearing.
* *Guaranteed works for KYAML* means: for every input in the defined KYAML
  language, `kyq` either accepts it and produces the specified output, or
  rejects it with a structured, locatable error; no silent mis-parse; no crash;
  behaviour is specified by an executable grammar, covered by property tests,
  and bounded by stated resource limits.
* *Guaranteed works for JCS* means the same, plus byte-for-byte determinism
  per RFC 8785, via the `ijson-jcs` contract (`check`/`fix`/`canon` semantics,
  trailing-newline rule, failure modes).
* The companion catalogue `docs/PROOF_OBLIGATIONS.adoc` lists the theorems
  that the finished product must satisfy. This ultraplan does *not* prove them;
  it sequences the work so proofs can be added without rework.
* *MetaManifold-WebUI* is a downstream consumer. This plan inventories its
  JSON/YAML boundaries and centralises its adapters, but does not rewrite its
  Julia/TypeScript architecture without explicit owner approval.

=== 0.4 What "kyaml" means today

* `coordination.k9` describes kyq as *an AffineScript-based KYAML processor
  intended as a smaller, K8s-aware alternative to yq* with target formats
  `YAML`, `JSON`, `K8s manifests`, YAML versions `YAML 1.2`, and K8s target
  `v1.25 → v1.30`. No formal KYAML grammar artifact exists. The intended
  meaning is *the subset of YAML 1.2 that Kubernetes actually emits and
  accepts*, plus K8s conventions (multi-doc `---`, anchors/aliases used
  sparingly, tags rare, `apiVersion`/`kind`/`metadata`/`spec` required shapes).
* Lint rules in `RequiredFields.affine` cover `required-field` for Pod,
  Deployment, Service, ConfigMap, Secret; `README.md` enumerates a broader rule
  set (`deprecated-api`, `latest-tag`, `selector-mismatch`, `resource-names`,
  `label-keys`, `type-check`, etc.) that does not yet exist as code.

=== 0.5 What "ijson-jcs canonical" means

* `hyperpolymath/ijson-jcs` is the estate JSON standard (D306): I-JSON
  validation (RFC 7493 MUST + SHOULD) plus JCS canonicalisation (RFC 8785),
  Rust crate + `ijson-jcs` CLI (`check`/`fix`/`canon`), with stated exit codes,
  trailing-newline rule (*canonical bytes optionally followed by exactly one
  `\\n` are accepted by `check`; `fix` always writes canon + `\\n`; `canon`
  writes canon with no trailing newline*), duplicate-key detection at parse
  time, IEEE-754 and safe-integer `±(2^53−1)` enforcement, UTF-16 code-unit key
  sorting, and denial of unpaired surrogates / noncharacters. The crate's test
  suite (33+ cases) is the executable spec.

== 1. Mathematical proof obligations (catalogue only)

The catalogue lives in `docs/PROOF_OBLIGATIONS.adoc`. Summary below; no proofs
are attempted here.

* *KYAML language*: totality + determinism of lex/parse; bijection between
  token streams and ASTs modulo insignificant whitespace/comments; YAML 1.2 core
  schema faithfulness for the KYAML subset; multi-document equivalence;
  anchor/alias resolution termination + referential transparency; tag handling.
* *K8s schema*: soundness of `required-fields` and type rules w.r.t. the
  embedded OpenAPI schemas (`apps/v1`, `v1`, `networking.k8s.io/v1`,
  `batch/v1`, etc.); completeness bounds; `deprecated-api` rule correctly
  tracks `v1beta1`→`v1` transitions; selector-mismatch detection is sound (no
  false negatives for the checked kinds).
* *Query + mutation language*: path query semantics (`a.b`, `[0]`, `[]`,
  quoted keys) are deterministic and total on well-formed docs; `get`/`set`/`del`
  preserve document well-formedness and K8s invariants where claimed; idempotence
  of `fmt`.
* *KYAML↔JSON bridge*: `to-json`/`from-json` are semantics-preserving on the
  intersection of the two languages; lossy cases are characterised and rejected.
* *JCS/I-JSON*: parsing rejects duplicate keys before `Value` construction;
  safe-integer and float canonicalisation exactly match `ijson-jcs`
  (`serde_json` with `float_roundtrip`, ES `JSON.stringify` number rules);
  UTF-16 sort is a total order matching RFC 8785; `to_jcs` is deterministic,
  idempotent, and injective on equivalence classes of JSON values modulo key
  order/whitespace; trailing-newline rule is exactly as specified; error types
  are exhaustive.
* *Cross-cutting*: a K8s manifest round-trips `YAML → Value → JCS bytes →
  Value → YAML` without semantic change outside declared normalisations;
  resource limits and error handling are proven not to mask invalid inputs.

== 2. Sequencing principle: Working → Canonical → Proven → Integrated → Evidenced

You cannot prove a tool correct before the tool exists, and you cannot claim
the canonical form works before the underlying YAML works. The ultraplan is
therefore strictly ordered:

[horizontal]
Phase 0 (now) :: Make the repository honest and green
Phase 1 (next) :: Establish facts — build/test + audit + inventory + coverage matrix
Phase 2 (after) :: Define format contracts — strict JSON/I-JSON/JCS/KYAML/app schemas
Phase 3 (then) :: Implement and harden kyq — complete consumption, number preservation, UTF-8/JCS, comment preservation, limits, diagnostics, check-vs-fix
Phase 4 (next) :: Package something genuinely usable — CLI/WASM pins, argv/stdin proof, installers, adapters
Phase 5 (after) :: Integrate MetaManifold-WebUI — centralise adapters, preserve semantics, YAML structural gates, KYAML emission, versioned persistence
Phase 6 (last) :: Evidence and acceptance — differential tests, corpus tests, round-trip/property tests, workflow validation, clean-install smoke tests, small PRs

Each phase has a *gate* that must pass before the next phase starts. No phase
is allowed to produce a placeholder artefact that earlier phases pretend is real.
The 40 steps from the handover are embedded verbatim below; numbers in
parentheses are handover step numbers.

== 5. Phase 2 — Define the format contracts (steps 6–10)

Gate to exit Phase 2: `docs/KYAML_SPEC.adoc` and `docs/IJSON_JCS_INTEGRATION.adoc`
normatively separate the six contract layers, cite pinned commits, and define
rejection vs silent-normalisation for every unsupported construct.

=== 5.1 Separate six contract layers (6)

* *strict JSON parsing* — raw-byte, duplicate-key, UTF-8, escape, surrogate,
  noncharacter, finite-number checks per RFC 8259 + I-JSON.
* *I-JSON value validation* — `±(2^53−1)` safe integer, top-level object/array
  SHOULD, control-char restrictions (RFC 7493).
* *JCS serialization* — UTF-16 key sort, ES number rules, no whitespace,
  deterministic bytes (RFC 8785).
* *KYAML conformance* — YAML 1.2 subset that Kubernetes emits/accepts.
* *compatibility YAML import* — permissive import for legacy YAML not yet KYAML;
  explicitly lossy, never used for canonical hashing.
* *application schemas* — K8s OpenAPI per-version (`apps/v1`, `v1`, etc.);
  optional, separate from generic parsing.

Each layer has its own error taxonomy; no layer may mask another's INVALID.

=== 5.2 Use ijson-jcs strict raw-byte parsing as JSON reference (7)

* `hyperpolymath/ijson-jcs` pinned to an explicitly recorded commit (record in
  `docs/IJSON_JCS_INTEGRATION.adoc` and `kyq_chora.deed` via `related`).
* kyq JSON parsing must be byte-for-byte equivalent to `ijson-jcs` strict
  `parse_json` — not via `serde_json::Value` -> map -> claim validation.
  Duplicate keys and numeric tokens are detected on raw bytes before map insertion.

=== 5.3 Resolve upstream vs adapter differences (8)

* Document explicitly where Julia (`JSON3.read`) and JavaScript (`JSON.parse`)
  diverge from `ijson-jcs` strict: exponent-form numbers (`1e2` vs `100`),
  exact integers beyond 53 bits, `-0` preservation, duplicate-key handling.
* Provide equivalence-tested adapters (Phase 4) that compensate, or declare
  the boundary as lossy-legacy with versioned migration.

=== 5.4 Define KYAML precisely (9)

* `docs/KYAML_SPEC.adoc` becomes normative: which YAML 1.2 features are in
  scope (block/flow collections, anchors/aliases, tags, directives, multi-doc
  `---`/`...`), which are rejected explicitly (not silently changed), and which
  scalar coercions apply.
* Valid YAML is not sufficient evidence of KYAML. Fixtures `examples/deployment.yaml`
  (good) and `tests/fixtures/invalid-deployment.yaml` (bad) plus spec examples
  are the first conformance tests.
* Unsupported constructs must be rejected with `path` + `line`/`column`,
  not flattened or dropped.

=== 5.5 Keep K8s schema/lint rules optional and separate (10)

* K8s lint rules (`required-fields`, `type-check`, `deprecated-api`,
  `latest-tag`, `selector-mismatch`, `resource-names`, `label-keys`) are
  separate from generic parsing/formatting. Running `kyq fmt` or `kyq canon`
  must not require K8s schemas; `kyq lint --k8s` does.

== 6. Phase 3 — Implement and harden kyq (steps 11–18)

Gate to exit Phase 3: kyq's lex/parse/emit is hardened per steps 11–18;
resource limits enforced; diagnostics are structured/bounded/redacted; check-vs-fix
separation proven; property tests pass.

=== 6.1 Complete input consumption and duplicate-key detection (11)

* Parser must consume entire input; trailing junk (`}{`, `,`, extra `---`) is
  `INVALID`, not silently ignored. Test: `valid_json + " trailing"` → INVALID.
* Detect duplicate decoded keys *before* map insertion. Escaped-equivalent keys
  (`"a"` vs `"\u0061"`) are duplicates if they decode to same string. Use
  raw-byte key tracking, not post-insertion dedup.

=== 6.2 Preserve number-token information (12)

* Retain original numeric token text until the applicable profile (I-JSON vs
  JCS vs K8s `type: integer`) has been checked. Never silently round exact
  integers; `9007199254740993` is distinct from `9007199254740992` and must be
  rejected as unsafe, not rounded.

=== 6.3 Handle UTF-8, escapes, surrogates, noncharacters, numbers, JCS ordering (13)

Per pinned `ijson-jcs` `src/*.rs`:

* UTF-8: reject invalid sequences; handle BOM per JSON spec.
* Escapes: `"` `\` `/` `b` `f` `n` `r` `t` `uXXXX`; no single-quote escapes.
* Surrogate pairs: `U+D800..U+DFFF` only as valid `high+low` pair forming
  `U+10000..U+10FFFF`; lone surrogates → INVALID.
* Noncharacters: `U+FDD0..U+FDEF`, `U+xxFFFE`, `U+xxFFFF`, `U+nFFFE/F` etc. → INVALID.
* Finite numbers: reject `NaN`, `Infinity`, `-Infinity`; handle `-0` distinctly.
* JCS UTF-16 key ordering: sort by UTF-16 code units per RFC 8785, not
  lexicographic bytes. Test with `"\uD83D"`-containing keys.

=== 6.4 Preserve comments and association (14)

* Use a lossless syntax representation (CST) where `fmt`/`set`/`del` run.
  Comments and their association with correct nodes (preceding, trailing,
  inline) must survive edits. No comment stripping on round-trip.

=== 6.5 Specify document streams, scalars, anchors, aliases, tags, merges (15)

* Document: `docs/KYAML_SPEC.adoc` must enumerate handling of document streams
  (`---`/`...`), scalar types (plain/quoted/block, chomping), anchors/aliases
  (acyclic, expansion limit), tags (`!`/`!!`), merge keys (`<<`), non-string
  keys, and conversions that cannot be lossless.
* Reject disallowed features in strict mode; do not flatten them silently.
  E.g. if `!!timestamp` is excluded, `2023-01-01` stays string in KYAML but
  error in strict K8s mode, not coerced to date.

=== 6.6 Resource limits (16)

* Enforce: byte size, nesting depth, token count, document count, anchor
  expansion factor. Defaults documented in `docs/KYAML_SPEC.adoc` and `kyq --help`.
* No arbitrary object construction, code execution, implicit environment
  expansion (`${VAR}` only via explicit `envsubst`), or external file/network
  resolution (`!include` → rejected).

=== 6.7 Structured, bounded, redacted diagnostics (17)

* Every error is `LintIssue`/`ParseErrorDetail` with `kind`, `path`, `line`,
  `column`, `message`. Messages are bounded (no dumping of entire 10 MB input)
  and redacted (no secrets, tokens, keys). Test: error for 1 MB input < 1 KB message.

=== 6.8 Separate check from fix (18)

* `kyq check` never modifies files. `kyq fix` uses atomic writes (write temp
  + rename) and never destroys invalid input (INVALID files left untouched).
  Exit codes: 0 canonical, 1 not-canonical, 2 invalid — per `ijson-jcs`.

== 8. Phase 5 — Integrate MetaManifold-WebUI (steps 24–32)

Gate to exit Phase 5: MetaManifold first-party JSON/YAML boundaries are
centralised behind adapters; semantics preserved; workflow structural gates
deployed; KYAML emitted for owned YAML; opaque data untouched; persistence
versioned.

=== 8.1 Centralise first-party adapters (24)

* Create `src/adapters/` (or `lib/kyq-adapter`) in MetaManifold-WebUI:
  single `parseRequest`, `encodeResponse`, `readConfig`, `writeConfig`,
  `validateBrowserPayload` entry points. No direct `JSON.parse` scattered.

=== 8.2 Validate original bytes before JSON.parse (25)

* Browser/Julia helper must read the response body as bytes: use
  `new Uint8Array(await response.arrayBuffer())` in the browser and
  `copy(response.body)` (`Vector{UInt8}` with HTTP.jl) or `read(stream)` for a
  Julia response stream. Pass those original bytes to `ijson-jcs` (via `kyq`
  WASM/FFI) validation and retain them for error reporting. Do not decode with
  `response.text()`/`String(...)` before validation: decoding may replace
  malformed UTF-8 or remove a BOM. Only after validation may the helper decode
  and parse JSON, preserving duplicates and numeric tokens until validation
  completes. Keep the retained byte buffer intact when decoding (in Julia,
  decode a copy because `String(::Vector{UInt8})` can take ownership).

=== 8.3 Preserve endpoint schemas (26)

* Endpoint adapters preserve optional/empty-body semantics (`204 No Content`
  vs `200 {}`), exact-count lexical rules (e.g. `count` must be integer
  `1..100`), and Oxygen.jl error handling. Test real `Oxygen.request()` not
  just helpers; snapshot existing curl fixtures.

=== 8.4 Documented error mappings (27)

* Expected input errors (malformed JSON, wrong shape, too large) → `400`/`413`/`422`
  per `docs/API_ERRORS.adoc`. Internal failures (DB down, panic) → `500`,
  never `400`. Do not conceal internal failures as client mistakes.

=== 8.5 Replace YAML-reading regex gates (28)

* Workflow linter (`kyq lint` for `.github/workflows/*.yml`) must use
  structural queries (`kyq get '.jobs.build.steps[].uses'`) not regex.
  Must read both `job-level` and `step-level` `uses:`/`run:`; comments and
  `run:` body decoys (`# uses: fake/action`) must not influence verdicts.
  Test with comment-injection mutants.

=== 8.6 Emit and check KYAML for owned YAML (29)

* All owned workflow/config YAML (`.github/workflows/*.yml`, `config/*.yaml`)
  is emitted via `kyq fmt` (canonical KYAML). `ci.yml` checks `kyq check`
  on them. Update path discovery, installers, examples, tests. Preserve
  mandatory consumer filenames: GitHub requires `.yml`/`.yaml` in
  `.github/workflows/` — do not rename to `.kyaml`.

=== 8.7 Preserve consumer-required file properties (30)

* `kyq fmt` for workflows must preserve: comments, action pin annotations
  (`# pin: sha`), `permissions:`, `expressions: ${{ }}`, multiline `run: |`
  scripts, scalar types (`on: push` stays string, not bool), array order.

=== 8.8 Do not rewrite opaque data (31)

* Vendor files, `actions.lock` (machine-generated by `gh actions-lock`),
  invalid fixtures (`tests/fixtures/invalid-deployment.yaml`), third-party
  JSON blobs, lockfiles are not reformatted indiscriminately. Record
  exceptions in `docs/COVERAGE_MATRIX.adoc` and `docs/KYAML_SPEC.adoc`
  compatibility boundaries.

=== 8.9 Version persistence changes (32)

* If persisted hash/signature format changes (JCS bytes → new JCS version),
  bump `formatVersion` field, retain old-record verification (`verify(v1)` and
  `verify(v2)`), and provide migration script. No silent ID changes or mass
  rehashing without owner approval.
