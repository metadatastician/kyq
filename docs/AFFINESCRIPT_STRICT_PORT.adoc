= kyq — Strict AffineScript-Only Port Plan (Path A)
:toc: macro

This note details the work implied by the owner's ruling *strict AffineScript
only* (2026-10-23). No Rust/Cargo code is added; `coordination.k9`
`affinescript-only` stays enforced. The plan turns the ROADMAP Blocker 1
breakdown into actionable upstream and in-repo tasks.

toc::[]

== Why this plan exists

`docs/status/ROADMAP.adoc` Blockers records the original 2026-10-07 result:
AffineScript 0.1.1 did not parse any of the then-9 tracked `.affine` files.
The 2026-10-24 A1 rerun supersedes that as the *current* state: the minimal
slice passes and 3 of the now-11 files pass standalone `check`, but 8 entry
points still fail and there is no full build/test/WASM PASS. Until the whole
tree compiles, `just build`/`test`/`wasm` still fail by design
(`no-fabricated-artefacts`). A Rust bootstrap would clear the blocker sooner,
but the owner explicitly rejected it — so we fix the AffineScript side. See
`docs/status/A1_GRAMMAR_CENSUS.adoc` for the run, exact diagnostics, and
ratchet.

== What the compiler gap is (from ROADMAP)

Roughly 5% mechanical, 25% semi-mechanical, rest rewrite:

* Mechanical: `module X;` needs its semicolon, `import` → `use`, no trailing enum
  commas, `&mut T` → `mut T`.
* Semi-mechanical: no variant named after a builtin type (`String`, `Int`).
  A1 disproved the earlier “two-segment paths only” claim: multi-segment paths
  and `#{…}` record literals both passed their probes.
* Rewrite: the probes reject legacy map-type syntax, `break`/`continue`, and
  working `if let` binding. The AST now uses association lists and passes
  `check`; parser/query control flow still needs structured equivalents.
  Generic `if let` tokens can parse as an `if` containing a let expression, so
  a parse-only result is not evidence of pattern-binding support.

== Upstream tasks (affinescript side)

A1 did not file upstream issues. Do not file the disproved path/record/use
claims as grammar gaps. Remaining candidates, each with a minimal reproducer,
are:

* Variant names that collide with builtin types, if upstream wants to support
  them; the in-repo `YamlString`/`YamlInt` spellings already avoid the issue.
* Container type: `Map<K,V>` or equivalent, with `contains`/`get`/`set`.
* Control flow: `break`/`continue` or structured loop alternative, `if let`
  (or `match` desugaring).
* WASM I/O: argv/stdin/stdout/stderr imports for the WASM target (blocker 3).
* Verify `affinescript check` covers imports: plant a type error in an
  imported module and confirm it is rejected.

== How KYAML guarantee is shown before proofs

* Executable spec: `docs/KYAML_SPEC.adoc` + `examples/deployment.yaml` (good) +
  `tests/fixtures/invalid-deployment.yaml` (bad) are the first conformance
  tests.
* Property harness (AffineScript test module, not Rust proptest yet): parse
  totality/determinism, `fmt` idempotence, `get`/`set` round-trip, selector
  soundness — each as an AffineScript test that runs via `affinescript test`
  once A1 clears.
* Shared corpus with `ijson-jcs`: valid/invalid/canonical JSON triples; `kyq
  canon` (AffineScript) and `ijson-jcs canon` (Rust oracle) must be byte-equal
  (Thm JCS-8). The oracle is external — no Rust code is added to kyq.

== Ordering

A1 → A2 → A3/A4 (parallel) → A5 → A6 (needs A2's `JsonValue`) → A7 → A8.
Phase 1 gate (KYAML working) is A1..A5 + `ci.yml` build/test green. Phase 2 gate
(JCS canonical) is A6 + corpus byte-equality. Proofs (Phase 3) are after both.
