= kyq architecture
:toc: preamble

kyq validates, canonicalises, formats and queries KYAML, I-JSON/JCS and
import-free Dhall. TOML 1.0 takes a separate validity-only path that never
projects TOML dates, times or source comments into the JSON value model. It is a native Rust library and command-line tool. This
page describes the repository as it stands. The feature boundary is
`README.adoc`. The status is `docs/status/NATIVE-INTEGRATION.adoc`, and the
plan for the remaining work is `docs/ULTRAPLAN.adoc`, section 13.

== Repository layout

`docs/architecture/REPOSITORY-MAP.adoc` is the generated, authoritative map of
every path. The main parts are:

[cols="1,3",options="header"]
|===
| Path | Contents

| `src/lib.rs`, `src/kyaml.rs`, `src/emit.rs`, `src/main.rs`
| The Rust implementation: the library, the KYAML reader, the formatter and
the command-line entry point.

| `src/*.affine`, `src/Kyaml/`, `tests/*.affine`, `benches/*.affine`
| Retained AffineScript sources. They are historical research and are not
built.

| `tests/*.rs`
| The native test suites, with inputs under `tests/fixtures/`.

| `verification/bounds/`, `verification/verus/`
| The resource-budget kernel with its Pearlite contract (Creusot), and a
separate Verus model. The ledger is `verification/PROOF-STATUS.adoc`.

| `verification/proofs/`
| The Agda theory spine and its Rocq recheck leg. The ledger is
`docs/status/PROOF-STATUS.adoc`.

| `conformance/`
| The JavaScript conformance oracle. It is an independent test oracle, not the
implementation.

| `examples/`, `templates/`
| Example Kubernetes manifests and manifest templates. The double-brace tokens
in the templates are kyq template parameters, not unfilled placeholders.

| `.github/`
| Workflows, community-health files and governance.
|===

== Processing pipeline

The tool reads one value-projectable format (`--from kyaml`, `json`, `jcs` or
`dhall`) into a value. `validate --from toml` instead uses an isolated TOML
1.0 validity-only parser with no conversion or output. KYAML input passes lexical checks and a bounded reader that
charges every node and alias expansion to a budget. The tool then validates
the value, writes JCS bytes through `ijson-jcs`, writes block KYAML, or
answers an RFC 6901 pointer query. `README.adoc` lists the commands. Machine-readable capability discovery
is a preview command, documented in `docs/CAPABILITIES.adoc`.

== Build

The `Justfile` is the build entry point: `just build`, `just test` and
`just check`. The Rust version is pinned in `rust-toolchain.toml`.
